# Amatsureika

Главная страница — локальная интерактивная SVG-карта, воссозданная по предоставленным изображению и видео. Без Canvas, WebGL и внешних библиотек визуализации. Три режима: ядро, кольца, соты. Узлы, связи и импульсы демонстрационные, не отражают реальную память.

## Запуск

Windows: установите Python 3.10+ и Node.js LTS с npm, запустите Start.bat. При ошибке окно остаётся открытым; журнал находится в logs/startup.log. Сервер работает, пока открыто окно. Если браузер не запустился, скопируйте адрес из окна. Start.bat --check проверяет запуск сборки без открытия браузера. Первый запуск требует сети для установки TypeScript; после установки сборка и сервер работают локально. Или выполните npm install, npm run build, python server.py.

Масштаб — колесо мыши или кнопки; перетаскивание — перемещение карты; клик по кластеру или узлу — подсветка связей. Панель позволяет менять режим, скорость, свечение и плотность линий. При системной настройке reduced motion анимация по умолчанию отключена.

Python — единственный сервер, Node.js используется только для сборки. SQLite используется для настроек оформления. Настоящая память и Cloud.ru пока не подключены.

## Расширение визуализации
Двойной щелчок по кластеру — плавное приближение, колесо — масштаб 8–6400% с четырьмя уровнями детализации. Настройки скрыты по умолчанию; чат без внешней рамки открывается кнопкой «Чат». В чате доступны локальные команды, а не ответы LLM. В настройках можно добавить узел, связать два последовательно выбранных кластера и создать производный демонстрационный узел без удаления исходных. Данные не сохраняются между перезапусками. Предел — 5000 узлов и 360 на кластер. SVG, без Canvas/WebGL.

## Единое оформление
Общий фон карты и чата, полупрозрачные плавающие настройки, SVG-символы кластеров, мягкое появление сообщений. Настройки скорости, свечения, связей, глубины, фоновой текстуры, интенсивности движения и появления текста сохраняются в `data/amatsureika.db` (SQLite, без дополнительных пакетов) и восстанавливаются независимо от порта сервера. Кнопка сброса возвращает стандартный дизайн. Демонстрационные воспоминания не сохраняются.

## SVG Geometry 4.0
Единый геометрический модуль, устойчивые идентификаторы узлов N1-1/S1-1, радиальные сектора и аксиальная сетка сот. Камера и режим сохраняются отдельно в SQLite. Поиск по имени кластера или точному ID узла, плавный перелёт. Один RAF управляет перемещением узлов и камеры; за пределами viewport узлы отсоединяются от SVG DOM, при длительных медленных кадрах снижается детализация. Математические тесты на 1000, 5000 и 10000 узлов проверяют конечность координат и коллизии; это не браузерный FPS-бенчмарк. Демонстрационные данные.

## Чистая радиальная карта
Радиальный и компактный режимы показывают точки без контуров и заливки секторов. Названия демонстрационных категорий и подпись ядра удалены; в настройках и поиске используются нейтральные идентификаторы C1–C21 и N/S. Внешние SVG-иконки круглые. Название приложения в шапке сохранено. Демонстрационные узлы остаются только для проверки геометрии, не являются реальной памятью.

## Organic radial geometry
В радиальном режиме ширина сектора зависит от числа узлов, ряды расположены по дугам с безопасным шагом. Центральное ядро уменьшено, внутренний радиус увеличен, внешние иконки отделены свободным пространством; оставлены две периферийные орбиты. Обычные точки уменьшены. Названия и обводки радиальных кластеров отсутствуют. Стресс-тесты включают неравномерные распределения до 10020 узлов; это проверки геометрии, не визуальная оценка FPS.

## Chat → Core → Cluster Memory 1.0
На чистой карте нет демонстрационных сообщений. После первой отправки появляется кластер; каждое сохранённое сообщение пользователя и локальное подтверждение занимают по одной точке. На 200 сообщениях автоматически создаётся пустой соседний кластер-продолжение. Следующие сообщения идут туда. Карта восстанавливается из SQLite `data/amatsureika.db`, нажатие на кластер показывает его архив. Видимые импульсы после подтверждённой записи проходят через центр к точке. Повтор одного request_id не создаёт дубликатов. Пока один хронологический поток, без смысловой классификации и LLM; ответ — явно локальное подтверждение. Настройки и камера сохранены. Тесты покрывают rollover 200, параллельные записи, повтор, перезапуск и геометрию до 50 кластеров.

## Living Memory 2.0
Кривые траектории, хвост из частиц, волна от ядра, разные оттенки запроса и подтверждения, спокойные архивы и цветовая преемственность. Индекс по кластерам, создание SVG только для видимой области, агрегированные штрихи на дальнем масштабе и ограничение очереди анимации; записи никогда не удаляются ради производительности. Активный кластер определяется сохранённой цепочкой, восстановление карты из SQLite, повтор POST с тем же UUID и сверка истории после сбоя. Проверка целостности при запуске и вручную, защита лимита в SQLite, при выявленной на старте аномалии запись блокируется без удаления данных. Геометрические тесты 10k/50k/100k и отдельная база из 100k сообщений. Это не измерение браузерного FPS; визуальная проверка на устройстве остаётся необходимой. Неподтверждённый черновик не обещано восстанавливать после закрытия браузера.

## Directed Memory 3.0 + Cloud.ru
Одна SVG-точка представляет до 500 фактически сохранённых сообщений. Новая появляется только при записи 501-го, 1001-го и т.д. Координаты стабильны, ряды растут вперёд от кольца, не вокруг. Физические страницы SQLite по 200 строк не мигрируются и не удаляются: API /api/memory создаёт логические блоки, архив показывает до 500 исходных записей. Кнопка Cloud.ru после кольца открывает модальное меню. Официальный Foundation Models API: https://foundation-models.api.cloud.ru/v1. Каталог загружается только вручную; выбранная модель хранится в SQLite. Ключ по умолчанию в памяти сервера, по явному согласию в незашифрованном data/cloud.key (игнорируется Git; не делитесь файлом). Можно задать CLOUD_RU_API_KEY. Платный запрос — только явный флажок на одно сообщение и подтверждение; лимит 512 выходных токенов, без автоматических повторов. При неопределённом сетевом исходе проверьте расход до повтора. Пока облачный запрос отправляет только текущий текст, без передачи архива. Реальный ключ и реальные платные вызовы в CI не используются.

## Quiet Flow 1.0
Мелкие независимые частицы по прямым линиям, без шлейфов и расширяющихся волн. При отправке: чат → ядро, для явно подтверждённого Cloud.ru запроса ядро → Cloud.ru, затем ожидание фактического результата HTTP. После подтверждённой записи в SQLite: Cloud.ru → ядро (только облачный запрос), ядро → чат и память. Локальный режим не рисует облачный обмен. Ошибка не запускает маршрут успешного ответа; повторная подтверждённая запись не рождает новых точек. Три частицы на участок, разные задержки и скорости, общий RAF, освобождение элементов при паузе/скрытии вкладки, мягкая подсветка прибытия. Автоматические тесты имитируют задержку, ошибку, повтор и локальный режим, реальных платных вызовов нет. Геометрия 500 сообщений на точку сохранена.

## Functional Orbit 1.0 — Работа и Документы
Четыре маленьких контурных значка на верхней правой дуге: Cloud.ru, Работа, Документы, Настройки. Работа — локальные справочники сотрудников, автомобилей и топливных карт, дневной табель с часами, журнал ГСМ с литрами и суммой; поиск, редактирование, архив и восстановление. Записи связываются по ID, не отправляются в облако. Документы — локальный виртуальный диск: папки, загрузка нескольких файлов (до 25 МиБ каждый), скачивание, переименование, поиск в папке, список/плитки, текстовый просмотр и корзина с восстановлением. Файлы лежат в data/Документы под внутренними ID, имена и дерево хранятся в существующей SQLite; переносите вместе всю папку data. Не удаляйте файлы вручную. Настройки открывают существующую панель по центру. Печать табеля, импорт Excel, перенос файлов между папками и полноценный просмотр PDF/DOCX пока не реализованы. Без новых зависимостей и внешнего хранилища.

## Functional Orbit 2.0
Три реальные геометрии: растущие радиальные дуги, концентрические круги и шестиугольная решётка. Плавное изменение позиций с сохранением ID и 500 сообщений на точку. Внешняя орбита рассчитывается по фактическому размеру карты, без муляжей модулей. При наведении подсвечивается реальная связь ядра, соседнего блока или диска; двойной клик приближает блок, подписи количества появляются при увеличении. Рабочие и файловые запросы запускают короткие независимые частицы и статус активности. Отдельный сектор показывает каждый фактический файл вне корзины, цвет модулей различается; есть полноэкранный режим с запасным режимом карты. Никаких дополнительных Cloud.ru вызовов.

## Live Data Sectors
В радиальном режиме все данные растут от общей внутренней окружности: переписка сверху, документы справа, работа слева пятью независимыми дугами (сотрудники, табель, карты, автомобили, ГСМ). Только реальные активные записи: 1 рабочая запись или 1 файл = 1 точка; чат — 500 сообщений. Значки вынесены за общую внешнюю окружность напротив своих секторов. Наведение показывает ограниченный веер связей; щелчок рабочей точки открывает соответствующую запись, файловой — сведения и скачивание. Новые точки получают короткий импульс от модуля после подтверждённой операции. Архив и корзина исключаются из карты, восстановление возвращает запись. В круговом и шестиугольном режимах рабочие и файловые дуги размещаются за радиусом памяти, без пересечений. Без дополнительных облачных запросов.

Орбита дополнена пятым значком «Чат» над сектором переписки. Он открывает и скрывает существующий чат, синхронизируется с кнопкой в шапке и полноэкранным режимом; наведение показывает связи с блоками памяти. Частицы настоящего запроса проходят через этот значок в обе стороны. Отдельной истории или базы нет.

## Cognitive Routing 1.0
Каждый запрос проходит значок чата → ядро → локальный поиск (SQLite FTS5, при недоступности ограниченный поиск). Индекс переписки обновляется триггерами; активные рабочие записи и текстовые файлы обновляются при поиске. Поддерживаются TXT/MD/CSV/JSON/LOG/TSV (до 256 КиБ текста) и DOCX с ограничением XML; PDF и сканы не извлекаются. Извлечённые цитаты имеют дату и ID, сортируются по совпадениям и свежести; возможные расхождения рабочих записей отмечаются эвристически. Точные запросы о количестве и явный поиск с достаточным совпадением отвечают локально; сложные вопросы не имитируют полноценное рассуждение. Анимация туда и обратно только к реально найденным точкам. Если включено предложение Cloud.ru, при недостаточности локального поиска пользователь видит точный контекст и отдельно подтверждает отправку; можно выбрать локальный ответ. План привязан к запросу, действует 5 минут, повторное платное исполнение не запускается автоматически. Контекст ограничен 6000 символами, максимум 512 выходных токенов. Номер топливной карты маскируется в индексе работы; прочие выдержки могут содержать персональные данные. Ответ сохраняется в существующую SQLite. Никаких новых зависимостей, локальной LLM или автоматических платных вызовов. Это лексический поиск и эвристики, не семантическая память или доказанная проверка истинности.

## Chat Tools 1.0
Чат без нижнего переключателя платных запросов. Если модель подключена и локального ответа недостаточно, появляется существующее окно предварительного просмотра контекста с явным подтверждением Cloud.ru. В меню «+» есть локальный режим (до перезагрузки), поиск по источникам без сохранения нового диалога, рабочие записи, документы, калькулятор, настройки модели, копирование и экспорт видимого диалога, возврат к текущей истории. Многострочный ввод: Enter отправляет, Shift+Enter переносит строку. У сообщений есть копирование, повторное использование вопроса и переход к кластеру. Остановка отменяет только подготовку до исполнения, не уже отправленный облачный запрос. Калькулятор — ограниченная арифметика Decimal без eval, сеть не используется. Без новых зависимостей.

## Chat Tool Engine 2.0
В меню «+» — «Отчёты и аналитика»: семь разрешённых инструментов локального чтения (ГСМ, табель, автопарк, карты, сотрудники, документы, целостность памяти). ГСМ и табель фильтруются по месяцу, суммы вычисляются Decimal, цены за литр взвешены по объёму, архивные записи и корзина не учитываются. Карты маскируются. Вывод до 500 строк с полными итогами и явным числом строк, CSV с защитой от формул Excel, копирование. Ядро распознаёт точные команды «Отчёт по ГСМ за 2026-11», «Отчёт по табелю за 2026-11», «Отчёт по автопарку», «Отчёт по документам», «Отчёт по памяти». Эти команды идут напрямую к разрешённому инструменту, не к облачной модели; результат и вопрос сохраняются как диалог, не как проверенный новый факт, показываются до 30 строк и полные итоги; анимация — до восьми фактических источников. Произвольный SQL, shell, доступ вне хранилища и автономные изменения не добавлены.

## Chat Tool Engine 3.0
Меню «Комплексные задачи» формирует команды в поле ввода; отправка остаётся действием пользователя. «Комплексный отчёт за 2026-11» запускает семь имеющихся отчётов и проверку аномалий последовательно; это отдельные снимки с датами формирования, не единый атомарный снимок. «Проверь аномалии» выявляет повторяющиеся ключи, архивные или отсутствующие ссылки, несоответствие карты автомобилю, нулевую стоимость и отклонение цены литра от медианы группы топлива и месяца более чем на 50% при пяти и более операциях. Замечания требуют проверки. «Сравни документы #1 и #2» сравнивает извлечённый текст (до 256 КиБ, 2000 строк, ограниченный diff); не PDF/OCR и не смысловой анализ. «Измени запись #1 поле job: Старший водитель» формирует предварительный просмотр разрешённого поля; запись меняется только после отдельного подтверждения и проверки версии и существующих правил Workspace, с атомарным журналом work_edit_audit и защитой повторного исполнения. В случае сбоя записи диалога уже выполненное изменение восстанавливается по журналу. Разрешены только перечисленные поля, без создания/удаления/массовых изменений. Все инструменты работают локально, без Cloud.ru.

## Agent Intelligence 4.0 — этап 1
Разрешённый реестр, ограниченный DAG (до 12 шагов), параллельные независимые чтения (3 потока), зависимая сводка, проверка структуры отчётов, журнал (2000 запусков), сохранение сценариев, повтор, SQLite-очередь однократных задач с восстановлением незавершённых чтений после перезапуска. Работает при запущенном сервере. Только read_local в сценариях; изменения и Cloud.ru не допускаются. Меню агента содержит реестр, журнал, очередь, выбор сценариев и ввод пробега. Прогноз ГСМ — среднее трёх предыдущих месяцев при наличии всех трёх; расход на 100 км — оценка по заправкам и явно введённому пробегу, не измеренное сгорание. Сверка карт — внутренние связи без внешних выписок. Поддержаны многокомпонентные команды отчётов и уточнение месяца предыдущей команды; контекст последних четырёх сообщений добавляется к предварительному просмотру Cloud.ru. Вложения локальных файлов до трёх, drag/drop загружает на локальный диск, извлечённый текст ограничен; облачная передача только после подтверждения. Безопасный ограниченный Markdown, сортировка/фильтрация таблиц отчётов, Excel XLSX и Word DOCX из текущих отчётов стандартной библиотекой Python (до 500 строк, итоги полные; ячейки Excel текстовые). Без новых зависимостей. Потоковое облачное API, embeddings, импорт Excel/CSV, автозаполнение табеля и полноценная причинная модель — отдельные этапы, пока не реализованы.

## Agent Intelligence 4.0 — этап 2
Cloud.ru использует потоковый Chat Completions SSE (stream=true); локальный сервер передаёт реальные части ответа NDJSON, сохраняет полный ответ только после [DONE]. Неполные потоки не сохраняются как готовые, автоматических повторов нет. Тесты на имитации, платный реальный вызов не выполнялся. Импорт через «+» принимает CSV/XLSX (первый лист, до 500 строк, 2 МиБ, точные названия полей, даты текстом, ссылки ID, формулы запрещены). Предварительный просмотр использует те же валидаторы в откатываемой транзакции, затем отдельное подтверждение повторно проверяет весь пакет и сохраняет атомарно с журналом. Табель заполняется по указанному сотруднику, периоду и часам, по желанию только будни (праздники не учитываются). Расширенный лексический поиск: FTS префиксы и локальные разреженные символьные векторы для вариантов слов, точные совпадения приоритетны; отсутствующие термины и пересечения источников помечаются. Это не нейросетевые embeddings и не доказательство причинности. При сбое некоторых отчётов резервный инструмент может вернуть только количество активных записей, помеченное partial; зависимые шаги не выполняются как успешные. Cloud.ru embeddings не подключены, поскольку требуют отдельного выбора сервиса и подтверждения стоимости. Никаких новых зависимостей.

## Cognitive Agent 5.0 — Интернет (этап 1)
Меню «Интернет и исследования»: явный публичный запрос, DuckDuckGo HTML (без ключа, может ограничить автоматические запросы), Google News RSS за неделю, чтение HTML/TXT, исследование до трёх разных доменов с одним уточнением запроса и пересечением терминов. Даты — метаданные источников, не подтверждение актуальности; вывод не заменяет фактчекинг. SQLite кеш 200 объектов/30 минут. Скачивание PDF/TXT/CSV/JSON до 5 МиБ на локальный диск; наблюдение до 20 URL с проверкой раз в час только при работающем сервере, выключение доступно. HTTPS с проверкой DNS публичных адресов, соединение с проверенным IP и TLS hostname, ограничение перенаправлений, размера и одновременных запросов. Запросы требуют явного запуска; фоновые наблюдения требуют отдельного согласия. Не отправляет SQLite, ключи или историю автоматически. Cloud.ru не используется. Интернет-результат можно явно перенести в чат. Тесты используют имитацию внешних сайтов, доступность поисковиков на конкретной сети не гарантируется.
